## Open-ended exploration

Use case: ui-mockup. Act as an independent product design director. Create ONE high-resolution landscape exploration board containing THREE genuinely different UI/UX concepts for the history experience of Ideal Day, a personal daily routine app. Each concept needs a readable mobile main history screen and a small flow diagram or follow-on activity history screen. Explore freely; propose your own best information architecture and interaction ideas, not merely three visual skins.
Problem brief: user loves home: calm near-black background, compact stacked activity rows, meaningful small category-colored line icons, soft white typography, muted grey supporting text, lime green actions and completions. Existing history is mediocre: big completion calendar with many fractions, an activity filter, and buried By activity list. Selecting an activity repeats almost the same calendar and Back exits home instead of restoring previous history. In activity workspace (e.g. Chin-up Bar / Visualization), View all history fails. Need credible intuitive whole-day history, activity discovery, activity-specific dated history, and explicit return paths. Reconsider flow.
Constraints: mobile first, desktop adaptable; existing palette #0a0c0f background #101316 surfaces #242a2e borders #eef1ec text #8d9692 secondary #b5d77d green; flat calm surfaces, restrained 10px corners, realistic 14–18px UI type, no gratuitous gradients or giant score dashboards. Completion is completed/planned saved occurrences, unknown missing days are not failures; today is in progress. Session durations exist only when actually timed. Invented sample data must be marked illustrative on board. No fabricated health trends or AI insights. Each concept should have a distinct short title and one-sentence rationale, plus legible visible controls showing how to browse all days, find one activity and return. You choose concepts independently. This is exploratory, not final. Produce a sophisticated design study, not a promotional poster.

## 01 — Calendar + Activities · Recommended

Use case: ui-mockup. Create a polished, implementation-accurate UI proposal board for Ideal Day. Landscape 3:2 high resolution. Show THREE large flat mobile UI screens side by side, each 390x780 logical pixels, not perspective device renders. Use tiny unobtrusive numbered captions above screens and a short flow strip below. Make screen text highly legible. Board title outside UI. Label bottom 'Design proposal · Illustrative data'. Do not use real personal data. Screen layout is compact and practical, not marketing.
Faithfully match existing app style: page #0a0c0f, cards #101316 or #15191d, borders #242a2e, text #eef1ec, muted #8d9692, green #b5d77d; little shadows, 10px radii, 12–16px insets, 44px controls, body 14–16px, headings 18px except a refined 28px serif date/title reminiscent of home date header. Small uppercase spaced metadata in green. Small regular line icons. Activity identity colors: Training lime, Light gold, Care rose, Recharge pale blue, Fuel peach. No gradients, glow, health score, streak trophies, bar charts, added global bottom navigation, or Notes/Assistant bar in history. Preserve calm breathing room without empty wastes.
Truthful data semantics: completed / planned counts come from saved occurrences, today in progress. Skipped and not scheduled and no saved day are distinct. Missing data is never failure. Historical activity rows are read-only with chevrons; no checkboxes suggesting they toggle. Explicit 'Correct this day' is secondary only on day detail. Times/durations only if actually recorded. Example Chin-up Bar / Visualization is a visualization countdown, not a reps workout; do not invent reps or sets. Activity detail has its own name, recent dated records, and optional calendar disclosure; never duplicate generic Track record calendar. Back returns to actual originating view and restores state.
